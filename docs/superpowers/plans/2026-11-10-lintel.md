# Lintel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web app that scans a small store, shows an AI agent failing to buy from it, installs WebMCP + x402 fixes, and proves the fix by having agents buy through a PayPal-settled x402 checkout.

**Architecture:** One Next.js app (deployed as one Render web service) contains four things: the Lintel dashboard, the API (scan, runs, merchant install), the hosted per-merchant agent endpoints (`/m/{id}/agent/*`, including the x402 `paypal-order` checkout), and a demo store ("Ridgeline Coffee Roasters") with a before/after mode. Two LLM-driven agents (Gemini via Vercel AI SDK): a headless HTTP agent and a browser agent (Playwright over Kernel CDP, or local Chromium in dev). SQLite holds scans, runs, steps, payment nonces, and orders.

**Tech Stack:** Node 20+, TypeScript (strict), Next.js 15 App Router, React 19, Tailwind CSS, Vitest (+ jsdom for `lintel.js`), better-sqlite3, `ai` + `@ai-sdk/google`, `@onkernel/sdk`, `playwright-core` (and `playwright` dev dependency for local Chromium), `zod`.

**Spec:** `docs/superpowers/specs/2026-11-10-lintel-design.md`

## Global Constraints

- Product name is **Lintel**. Never use "Agent Ready" as our name (it is a PayPal product).
- PayPal is **sandbox only**: base URL `https://api-m.sandbox.paypal.com`. No live endpoints anywhere.
- x402 message shape: `x402Version: 2`, scheme `"paypal-order"`, network `"paypal:sandbox"`, asset `"USD"`. Headers: `PAYMENT-REQUIRED` (402 response), `PAYMENT-SIGNATURE` (client retry), `PAYMENT-RESPONSE` (200 response). Header values are base64 of JSON.
- No blockchain, no PYUSD.
- LLM: Gemini via free AI Studio key, env `GOOGLE_GENERATIVE_AI_API_KEY`. Model list from env `GEMINI_MODELS` (comma-separated), default `gemini-3.5-flash,gemini-3-flash-preview,gemini-2.5-flash`. No Anthropic or other paid keys.
- Free-tier budget: headless agent max **12** steps, browser agent max **20** steps per run.
- Secrets only from `.env` (already exists, gitignored). Commit a `.env.example` with empty values. Never log secret values.
- Payment approval baseline is human-in-the-loop via PayPal approve link; approval wait timeout `APPROVAL_TIMEOUT_MS` default `300000`.
- `PUBLIC_BASE_URL` env (default `http://localhost:3000`) is used for PayPal return URLs and for agent target URLs.
- `BROWSER_PROVIDER` env: `local` (Playwright Chromium, dev default) or `kernel` (requires `KERNEL_API_KEY`; Kernel cannot reach localhost, so `kernel` only works against the deployed URL).
- License: MIT. Public repo. README must contain run steps and the sandbox test buyer account.
- Out of scope for this plan: autonomous (vaulted) PayPal payments, real-store fix installation, Shopify/Woo packaging.
- Deadline: Nov 12, 2026 12:00 PM PST. Tasks are ordered so the demo-critical path (Tasks 1–9, 11–12) lands first; Task 10 (browser agent) can be dropped to headless-only if time runs out.

## Review Focus

1. **Gemini returns 503/429/404 mid-run** → retry with backoff, then fall back to the next model; if all fail, the run ends with status `failed` and a readable reason, never hangs. Test: Task 7 `llm.test.ts › falls back to next model on 503` and `› throws LlmUnavailableError after all models fail`.
2. **Buyer never approves (or cancels) the PayPal payment** → agent stops waiting at `APPROVAL_TIMEOUT_MS`, run ends `failed` with "Payment approval timed out", no capture attempted. Test: Task 9 `headless.test.ts › stops when approval times out`.
3. **Agent retries the paid request twice (replayed proof)** → second call returns the same receipt with 200 and does not capture again. Test: Task 3 `paypalScheme.test.ts › replayed proof returns stored receipt without second capture`.
4. **Scanning a real store that is slow, blocks us, or returns non-HTML** → scan finishes with partial results and a `site_unreachable` finding instead of throwing. Test: Task 8 `checks.test.ts › unreachable site yields partial scan`.
5. **Bad cart input from an agent** (unknown SKU, qty 0/negative/21+, empty items, non-JSON body) → 400 with a clear message, no PayPal order created. Test: Task 5 `checkout.test.ts › rejects invalid carts without creating orders`.

### Task 3: x402 `paypal-order` scheme

**Files:**
- Create: `src/lib/x402/paypalScheme.ts`, `tests/paypalScheme.test.ts`

**Interfaces:**
- Consumes: `PayPalApi` (Task 2), `getDb()` (Task 1).
- Produces:
  ```ts
  export const SCHEME = 'paypal-order', NETWORK = 'paypal:sandbox';
  export interface PaymentRequirement { scheme: 'paypal-order'; network: 'paypal:sandbox'; amount: string; asset: 'USD'; payTo: string; maxTimeoutSeconds: 900; resource: string; description: string; extra: { orderId: string; approveUrl: string; nonce: string } }
  export interface PaymentRequired { x402Version: 2; error?: string; accepts: PaymentRequirement[] }
  export interface PaymentPayload { x402Version: 2; scheme: 'paypal-order'; network: 'paypal:sandbox'; payload: { orderId: string; nonce: string } }
  export interface SettlementReceipt { success: true; network: 'paypal:sandbox'; transaction: string /* captureId */; paypalOrderId: string; amount: string; payer?: string }
  export function encodeHeader(obj: unknown): string; export function decodeHeader<T>(value: string): T; // base64 JSON
  export function cartHash(items: { sku: string; qty: number }[]): string; // sha256 hex of JSON of items sorted by sku
  export async function createPaymentRequired(args: { paypal: PayPalApi; merchantId: string; amount: string; items: {sku:string;qty:number}[]; resource: string; description: string }): Promise<PaymentRequired>;
  export type SettleResult = { ok: true; receipt: SettlementReceipt; firstSettlement: boolean } | { ok: false; httpStatus: 400|402; error: 'invalid_payload'|'unknown_nonce'|'cart_mismatch'|'order_mismatch'|'payment_not_approved'|'amount_mismatch'|'capture_failed' };
  export async function verifyAndSettle(args: { paypal: PayPalApi; merchantId: string; items: {sku:string;qty:number}[]; amount: string; header: string }): Promise<SettleResult>;
  ```
- Behavior: `createPaymentRequired` makes nonce `crypto.randomBytes(16).toString('hex')`, creates PayPal order with `customId = nonce`, `returnUrl = {publicBaseUrl}/api/paypal/return`, `cancelUrl = {publicBaseUrl}/api/paypal/return?cancel=1`, inserts `payment_nonces` row (`pending`). `payTo` = `merchantId`. `verifyAndSettle` order of checks: decode (bad → `invalid_payload` 400) → scheme/network match (else `invalid_payload`) → nonce row exists for merchant (else `unknown_nonce` 400) → row `settled` → return stored receipt with `firstSettlement:false` → `cart_hash` equals `cartHash(items)` (else `cart_mismatch` 400) → `paypal_order_id` equals payload orderId (else `order_mismatch` 400) → `getOrder`: status not `APPROVED` → `payment_not_approved` 402; amount or customId mismatch → `amount_mismatch` 400 → `captureOrder` not COMPLETED → `capture_failed` 402 → store receipt, mark `settled`, insert `orders` row, return `firstSettlement:true`.
